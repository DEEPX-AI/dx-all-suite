## The prompt

> The exact natural-language prompt given to the agent (verbatim):

```
Build a domain-optimized YOLO26n detection showcase on DEEPX NPU using the Ultralytics local Python package (Option 1). Do ALL of: (1) BASELINE — take stock yolo26n.pt, export to DeepX with format=deepx, then measure NPU inference FPS and accuracy (mAP50-95) on the Ultralytics african-wildlife validation split; (2) RETRAIN yolo26n on the Ultralytics african-wildlife dataset on the local GPU with a modest epoch count (around 40); (3) IMPROVED — export the retrained model with format=deepx, then measure NPU FPS and accuracy the same way; (4) write report.md comparing baseline vs improved (FPS, mAP) with a short analysis.
```

## Results (real, measured on DX-M1)

`african-wildlife` val split — 225 images / 379 instances, 4 classes (buffalo, elephant, rhino, zebra), INT8, `imgsz=640`.

| Metric | Baseline (stock `yolo26n`, COCO 80-cls) | Improved (retrained, 4-cls) | Δ |
|---|---|---|---|
| **mAP50-95** | 0.001 | **0.791** | **+0.790** |
| **mAP50** | 0.0015 | **0.943** | +0.942 |
| **NPU FPS** | 56.99 | **80.55** | **+41%** |
| NPU ms/img | 17.55 | 12.42 | −5.13 |

- **INT8 ≈ fp32**: the retrained model scored mAP50-95 0.792 (fp32, GPU) vs 0.791
  (INT8, NPU) — DeepX EMA calibration preserved accuracy.
- **Domain model is faster on the NPU (+41%)**: same `yolo26n` backbone, but the
  retrained head has `nc=4` vs the stock `nc=80`, so the NPU decodes far fewer class
  channels per image. Domain specialization buys **both** accuracy and latency.

See [`report.md`](./report.md) for the full analysis and per-class mAP.

## Files (all agent-generated)

| File | Role |
|------|------|
| `acquire.py` | fetch `yolo26n.pt` (Ultralytics auto-download) |
| `train.py` | retrain `yolo26n` on `african-wildlife` (local GPU, ~40 epochs) |
| `export_deepx.py` | one-shot `export(format="deepx")` for a `.pt` → `*_deepx_model/` |
| `measure.py` | NPU FPS + mAP via the Ultralytics DeepX backend → `metrics_*.json` |
| `verify.py` | assert both DeepX models exist + metrics are populated |
| `setup.sh` / `run.sh` | env setup / re-measure both models |
| `report.md` | baseline-vs-improved report |
| `metrics_baseline.json` / `metrics_improved.json` | the measured numbers |
| `session.log` | the build's real command output |

> Model binaries (`*.pt`/`*.onnx`/`*.dxnn`) and the `runs/` training outputs are **not
> committed** — they are regenerated by the pipeline below.

## Reproduce

```bash
bash setup.sh                 # verify the dx_rt venv (ultralytics + dx_engine + dx_com)
python acquire.py             # download yolo26n.pt
python export_deepx.py yolo26n.pt yolo26n_baseline_deepx_model    # baseline → DeepX
python train.py               # retrain on african-wildlife (GPU)
python export_deepx.py runs/train/weights/best.pt yolo26n_improved_deepx_model
bash run.sh                   # measure both on the NPU → metrics_*.json
```

(`run.sh` auto-detects the suite root and uses `dx-runtime/venv-dx-runtime`; if
`dx_engine` is missing, build dx_rt: `cd dx-runtime && bash install.sh --all
--exclude-app --exclude-stream`.)
