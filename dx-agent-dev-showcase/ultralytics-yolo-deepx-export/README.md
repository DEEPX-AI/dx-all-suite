## The prompt

> The exact natural-language prompt given to the agent (verbatim):

```
Export the Ultralytics YOLO26n detection model to DeepX NPU format using the one-shot format=deepx export path, then run inference on the Ultralytics bus sample image.
```

## What the agent does (KB-driven workflow)

With the Ultralytics integration knowledge added to `.deepx/`, the agent resolves
this prompt **without fabricating a pipeline**:

1. **`/dx-skill-router`** → classifies the task as model compilation.
2. **Suite routing** → `Ultralytics YOLO .pt → DeepX (format=deepx)` → `dx-compiler/CLAUDE.md`.
3. **dx-compiler routing** → `Ultralytics, YOLO, .pt, format=deepx` →
   [`.deepx/toolsets/ultralytics-deepx-export.md`](../../dx-compiler/.deepx/toolsets/ultralytics-deepx-export.md).
4. **`/dx-agent-compiler-convert` Phase 0** → recognises a YOLO **detection** model
   targeting DeepX → selects the one-shot path over manual PT→ONNX→`dxcom`.
5. **Export → compile → deploy → verify**, producing the files below.

The agent applies the KB's hard constraints: **x86-64 Linux only**, **detection
only**, **INT8 enforced**, output is a **directory** (`*_deepx_model/`), and the
`dx_engine` runtime comes from **`dx_rt`** (`dx-runtime/install.sh --exclude-app
--exclude-stream`) — not pip.

## Files (all agent-generated)

| File | Role |
|------|------|
| `export.py` | One-shot `YOLO("yolo26n.pt").export(format="deepx")` → `yolo26n_deepx_model/` |
| `infer.py` | Load `yolo26n_deepx_model/` and run NPU inference on the bus sample |
| `verify.py` | Validate the exported artifacts (`.dxnn` / `config.json` / `metadata.yaml`) |
| `setup.sh` | Verify deps in the `dx_rt` venv (ultralytics + dx_engine + dx_com) |
| `run.sh` | One-command: export → verify → inference |
| `expected_output.txt` | The real run's output (export + 5 detections + verify PASS) |

## Run it

```bash
bash setup.sh     # verify deps (ultralytics + dx_engine + dx_com in the dx_rt venv)
bash run.sh       # export yolo26n.pt → verify → run inference on bus.jpg
```

`run.sh` auto-detects the suite root and activates `dx-runtime/venv-dx-runtime`.
If `dx_engine` is missing, build the runtime: `cd dx-runtime && bash install.sh
--all --exclude-app --exclude-stream` (dx_rt provides `dxrt-cli` + `dx_engine`;
dx_app/dx_stream are not needed). See
[`expected_output.txt`](./expected_output.txt).
