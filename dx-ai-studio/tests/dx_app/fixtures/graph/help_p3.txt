Run a multi-model pipeline described entirely by a node-graph JSON
file. Changing which models run is a text edit, never a rebuild.

Usage: ./bin/multi_model_graph_sync --graph <file.json> [options]
       ./bin/multi_model_graph_sync --check <file.json> [--model-dir <dir>] [--json]
       ./bin/multi_model_graph_sync --list-models [--consumes <roi|frame|either>] [--produces <shape>]
                     [--model-dir <dir>] [--json]
       ./bin/multi_model_graph_sync --list-ops [--json]

Options:
  --graph <file>        the node-graph JSON to run
  --input [<source>=]<uri>
                        override a source node's "uri" (image/video path,
                        camera:<N>, rtsp://...). Repeat it once per source;
                        a graph with several sources needs <source>=
  --output <file>       write the rendered result. .mp4, .avi or .mkv: one
                        video. Any other extension: an image; a multi-frame
                        source writes <stem>_<index><ext>, and a live source
                        (camera:, rtsp://) then needs --frames N. With
                        several sources, one file per stream: the video
                        <stem>_<source_id><ext>, or images, always numbered:
                        <stem>_<source_id>_<index><ext>
  --display             show each rendered frame in a window; q or ESC stops
                        the run as Ctrl-C does. With several sources, one
                        window: a grid of the streams, each cell labelled
                        with its source id
  --draw <id[,id...]>   draw only these nodes (a logic node's id draws its
                        overlay) in the window, --output and --output-layers;
                        every node still runs and reports. The events panel
                        lists only these nodes' events
  --output-layers <dir> per frame, write the clean frame
                        (<stem>[_<source>]_<frame>_base.png), each drawn
                        node's drawing alone on a transparent RGBA PNG
                        (..._<frame>_<node>.png; ..._events.png for the events
                        panel) and <dir>/layers.json, listing them in stacking
                        order. <stem>: --output's, else the graph file's. A
                        video or live source needs --frames N
  --report <file>       write every FrameReport as JSON, ordered by
                        (node, parent_index, roi_index)
  --report-timing       with --report: add each frame's "node_ms", the
                        time per node. Off by default, so the sync and
                        async reports stay byte-identical
  --events <file>       write every event of the graph's logic nodes, one
                        JSON object per line (JSONL); they are printed as
                        [EVENT] {...} lines too
  --model-dir <dir>     where the .dxnn files live
                        (default: <dx_app>/assets/models)
  --max-inflight <N>    frames in flight at once (default: 16, at least 1).
                        multi_model_graph_async only
  --max-jobs-per-stage <N>
                        jobs one stage may have outstanding across frames
                        (default: 0 = no limit). multi_model_graph_async only
  --stall-timeout-ms <N>
                        fail when work is outstanding and nothing completes
                        for N ms (default: 0 = wait forever).
                        multi_model_graph_async only
  --frames <N>          stop after N frames (default: all); with several
                        sources, N frames of each stream
  --loop                a video source starts again at its end, so the run
                        goes on until Ctrl-C, q/ESC or --frames N (Live)
  --check [<file>]      validate the graph and list the model files it
                        needs, without opening the NPU, then exit.
                        Exit code reflects the graph itself; a missing
                        .dxnn is reported but is not an error here; a .dxnn
                        that cannot load here (not a .dxnn, or v9 before
                        DX-RT 3.5.0) is one (exit 1)
  --list-models         print every model this build can put in a graph, with
                        its published flag and the container version of its
                        .dxnn in --model-dir (v8, v9, missing; and when this
                        DX-RT cannot load it, why), then the
                        alias_of names of other models
  --consumes <what>     with --list-models: roi | frame | either
  --produces <shape>    with --list-models: boxes, obboxes, instances,
                        keypoints, labelmap, densemap, image, scores,
                        vector, boxes3d
  --json                with --check, --list-models or --list-ops: one JSON
                        document on stdout instead of the tables (README)
  --list-ops            print every logic and cpu op a graph can use: its
                        inputs, output, events and params (--json: the
                        catalog a front end builds its palette from)
  --help                this message
